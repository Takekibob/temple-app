## 4. トップ5の検出問題

### 問題1: イベント前日・当日朝の自動LINE配信が v2.2 要件だが実装確認不可 ⚠️ 高優先度

**現状**: LineSequence に FIRST_EVENT_ATTEND と LINE_REGISTER トリガーしかない
**v2.2 要件**: イベント申込後、前日にリマインダー + 当日朝にリマインダー送信
**推測**: `/admin/line/sequences` のトリガー拡張が必要だが、実装状況不明
**対応**: スケジュール配信エンジンの実装確認 + トリガー追加

### 問題2: お知らせ + LINE配信がワークフロー的に分断している ⚠️ 中優先度

**現状**: `/admin/announcements` で作成 → `/admin/line/messages` で別途配信
**問題**: 管理者が「どの告知がどこまで配信されたか」把握困難
**改善案**: 
- お知らせ作成時にLINE配信を同時選択可
- またはお知らせ詳細から「LINE送信」ボタン

### 問題3: LINE統計・成功率ダッシュボードが見当たらない ⚠️ 中優先度

**現状**: `/admin/line` に「送信数」「配信種別」表示のみ
**欠落**: 開封率、配信失敗数、セグメント別成功率
**対応**: `/admin/line/analytics` 新規追加推奨

### 問題4: フォロワー一括操作機能がない ⚠️ 中優先度

**現状**: タグ付け・メモ追加が個別対応
**スケーラビリティ**: 100名以上は実務困難
**対応**: 複数選択 + 一括タグ付け UI 実装

### 問題5: 会員インポートの DANKA/GOEN が v2.2 で廃止予定なのに UI にまだ残っている ⚠️ 低優先度だが要対応

**現状**: `/admin/members/import` の CSV サンプルに DANKA/GOEN が記載
**影響**: 新規導入時に廃止属性を参照する可能性
**対応**: サンプル削除、デフォルト値変更

## 7. リスク & 注意点

### リスク1: LINE方針転換による既存機能の扱い

**リスク**: お寺別LINE（Temple.lineOfficialUrl）が schema に残っている
**影響**: v2.3 廃止時に過去データ移行が必要
**対応**: 
- v2.2 で新規設定を禁止（UI 非表示）
- v2.3 で削除予定を事前告知
- マイグレーション計画書作成

---

### リスク2: LINE配信の個人情報取り扱い

**リスク**: LineMessage.targetMemberIds に複数member ID を保存
**影響**: GDPR/個人情報保護法対応の確認必要
**対応**: 暗号化 & アクセスログ記録確認

---

### リスク3: 大規模利用時のLINE API レート制限

**リスク**: 1,000名以上への同時配信時に LINE API の制限に引っかかる可能性
**影響**: 配信遅延・失敗
**対応**: キューイング + リトライロジック確認（推測: `/api/line/messages` で実装済みだが、流量テスト必要）
